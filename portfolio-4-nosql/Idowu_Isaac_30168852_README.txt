MongoDB catalogue model
Catalog.js uses embedded product attributes for a simulated IsaacMart catalogue, with schema validation and a unique SKU index. Headphones, clothing and lamps need different fields, so a flexible attributes object avoids many nullable SQL columns. MongoEvidence.txt shows insertion, a battery-hours query, an update, duplicate-SKU rejection and invalid-document rejection. Only three catalogue documents are used; no scalability benchmark is claimed.

The product _id is the relational product_id. Names in the catalogue are illustrative customer-facing descriptions; SQL seed names are generic. PostgreSQL owns stock, prices, orders and payments; MongoDB owns descriptive attributes. No live cross-store synchronisation is implemented. A transactional outbox plus idempotent consumer would propagate product lifecycle changes, with reconciliation for missing/orphaned catalogue records. Cross-store foreign keys and atomic transactions are absent. Eventual consistency is acceptable for descriptions, but checkout must verify authoritative SQL stock and price.

Embedding is suitable for bounded attributes read with one product. Unbounded reviews should be separate documents. A batteryHours index might help at scale but adds write overhead and is unnecessary for this three-document demonstration. The local MongoDB container has no published port and is only a development demonstration; production requires authentication, TLS and least privilege.
