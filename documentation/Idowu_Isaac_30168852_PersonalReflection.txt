1. Design decision

I understood why unit_price is stored in OrderItems. It records the price charged when an order was placed. If the current product price changes later, previous orders must retain their original prices.

2. Query optimisation

In my Codespace, the customer-history query changed from a parallel sequential scan followed by sorting to an index scan using orders_customer_date_idx. Execution time fell from 13.326 ms to 0.131 ms, approximately 102 times faster in this single comparison. These timings are specific to this test.

3. Transactions and concurrency

I reproduced a two-session locking test. The first transaction held a product-row lock, and the second session reached its two-second lock timeout. Rolling back the first transaction restored stock to 98.

A guarded update using WHERE stock >= requested_quantity prevents a decrement when insufficient stock remains, provided the application checks that one row was updated. My locking test demonstrated contention; it did not directly test two competing guarded purchases.
